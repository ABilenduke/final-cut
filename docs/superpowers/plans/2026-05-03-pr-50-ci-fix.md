# PR #50 CI Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get the three failing CI checks on PR #50 (`refactor/page-content`) passing — **Frontend Build**, **E2E Tests**, **CodeQL** — without regressing existing tests or losing the cross-location sitemap contract.

**Architecture:**
- **Frontend Build + E2E share one root cause.** `@nuxtjs/sitemap@6.1.5` was added on this branch. Its transitive dep `nuxt-site-config@2.2.21` pulls in `h3@2.0.1-rc.20` and registers a Nitro plugin that calls `useNitroOrigin(event)` on every request. h3 v2's `getRequestHost` does `event.req.headers.get(...)` (Fetch-style `Headers`), but Nitro 2.13.3 hands it a v1-shape event whose `req.headers` is a plain Node `IncomingMessage` object — no `.get` method. Every prerender route (`/contact`, `/faq`, `/accessibility`, `/careers`, `/private-screenings`) crashes 500 during `deno task build`. The build exits 1, which also breaks E2E because the docker compose `--build --wait` step fails before Playwright ever runs.
- **Resolution path for build:** replace the `@nuxtjs/sitemap` module with a hand-rolled `server/routes/sitemap.xml.ts` Nitro route. The sitemap contract in `docs/architecture/SITE_ARCHITECTURE.md` already specifies the URL set (movies, events, locations, blog, static pages); we own the data sources, so the module is replaceable. This removes `nuxt-site-config` entirely and resolves the version conflict at the dependency level. Fallback strategy in Task 3 in case downgrade is preferable.
- **CodeQL alert is a known design choice.** `frontend/app/composables/useGeolocation.ts:90` writes coarsened (~1 km) lat/lng to `sessionStorage`. Already documented in code via inline comment + the architecture doc. The architecture explicitly designed this cache; the right move is to dismiss the alert with rationale via the GitHub API, not contort the implementation.

**Tech Stack:** Nuxt 4 (Deno), `@nuxtjs/sitemap` (being removed), Nitro 2.13, h3 1.15, Playwright, GitHub Actions, CodeQL.

Create `frontend/server/utils/sitemap-builder.ts`:
```ts
export interface SitemapEntry {
  loc: string
  lastmod?: string
}

const XML_ESCAPE: Record<string, string> = {
  '&': '&amp;',
  '<': '&lt;',
  '>': '&gt;',
  '"': '&quot;',
  "'": '&apos;',
}

function escapeXml(value: string): string {
  return value.replace(/[&<>"']/g, (ch) => XML_ESCAPE[ch] ?? ch)
}

function absolutize(siteUrl: string, loc: string): string {
  if (/^https?:\/\//i.test(loc)) return loc
  const trimmedSite = siteUrl.replace(/\/+$/, '')
  const path = loc.startsWith('/') ? loc : `/${loc}`
  return `${trimmedSite}${path}`
}

export function buildSitemapXml(siteUrl: string, entries: SitemapEntry[]): string {
  const urls = entries
    .map((entry) => {
      const loc = escapeXml(absolutize(siteUrl, entry.loc))
      const lastmod = entry.lastmod ? `\n    <lastmod>${escapeXml(entry.lastmod)}</lastmod>` : ''
      return `  <url>\n    <loc>${loc}</loc>${lastmod}\n  </url>`
    })
    .join('\n')

  return `<?xml version="1.0" encoding="UTF-8"?>\n<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">\n${urls}\n</urlset>`
}
```

```ts
import { buildSitemapXml, type SitemapEntry } from '../utils/sitemap-builder'

const STATIC_ENTRIES: SitemapEntry[] = [
  { loc: '/' },
  { loc: '/movies' },
  { loc: '/whats-on' },
  { loc: '/events' },
  { loc: '/food-drink' },
  { loc: '/locations' },
  { loc: '/faq' },
  { loc: '/contact' },
  { loc: '/accessibility' },
  { loc: '/careers' },
  { loc: '/gift-cards' },
  { loc: '/private-screenings' },
  { loc: '/blog' },
]

const EXCLUDED_PREFIXES = ['/purchase/', '/account', '/auth/'] as const

function isExcluded(loc: string): boolean {
  return EXCLUDED_PREFIXES.some((prefix) => loc === prefix || loc.startsWith(prefix))
}

export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig(event)
  const siteUrl = config.public.siteUrl || 'https://finalcut.test'

  // Dynamic URLs come from the existing Nitro endpoint that the architecture
  // doc designates as the sitemap source. It returns Array<SitemapEntry>.
  const dynamic = await $fetch<SitemapEntry[]>('/api/__sitemap__/urls', {
    headers: { accept: 'application/json' },
  }).catch(() => [] as SitemapEntry[])

  const entries = [...STATIC_ENTRIES, ...dynamic].filter((e) => !isExcluded(e.loc))
  const xml = buildSitemapXml(siteUrl, entries)

  setHeader(event, 'content-type', 'application/xml; charset=utf-8')
  setHeader(event, 'cache-control', 'public, max-age=900, s-maxage=900')
  return xml
})
```

## Task 7: Dismiss the CodeQL alert with documented rationale

## Rollback / Plan B

If Task 4's hand-rolled sitemap approach fails in production-equivalent testing for any reason (e.g. dynamic URL fetch flakiness during prerender that we cannot work around), the fallback is:

1. Revert Tasks 3–4 with `git revert <sha> <sha>`.
2. Pin `@nuxtjs/sitemap` to a version known to work with h3 v1: try `5.x` (last release before the nuxt-site-config@2 split-out). Apply by editing `frontend/deno.json` to add an explicit dependency override:
   ```json
   {
     "imports": {
       "@nuxtjs/sitemap": "npm:@nuxtjs/sitemap@5"
     }
   }
   ```
   Then `deno task postinstall` and re-run Task 5/6 verification.
3. If neither v5 nor a hand-rolled approach work, the last resort is upgrading to Nitro 3 (which natively uses h3 v2). That is a much larger change and out of scope for this PR — file a follow-up issue and revert this branch's sitemap addition entirely until the upgrade lands.

The plan as written assumes Plan A (replace the module) succeeds; Plan B is documented only for the unblock-yourself-fast scenario.
